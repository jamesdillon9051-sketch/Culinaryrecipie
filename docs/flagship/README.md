# Flagship recipes: workflow, evidence record and cook's checklist

`src/data/flagship.json` lists about 20 recipes to bring up to a documented standard first. **The selection is provisional.** It was made on 27 October 2026 without Search Console data, on these grounds:

- dishes searched for in the five target countries,
- spread across cuisines, courses and methods,
- of manageable difficulty,
- with complete content: a photograph, calculated nutrition, every stage timed and a settled dish role.

Replace it once impressions and clicks are available. `status.md` beside this file is regenerated by `node tools/flagship-check.js` (part of `npm run check`) and is the current list.

## Three statuses, kept apart

| Status | Who sets it | Where | Shown on the page |
| --- | --- | --- | --- |
| **Automated checks** | The build, every time | Computed by `src/lib/flagship.js`, never typed | No. Every published recipe passes the audits; it is not a distinction. |
| **Editorial review** | A named person who read the page against the checklist below | `editorial` in `flagship.json` | Yes, as "Read and edited against the site's checklist by NAME on DATE", only while `recipeVersion` matches the recipe's current content version. |
| **Kitchen preparation** | A named person who cooked the recipe | `kitchen[]` in `flagship.json`, **and** `src/data/testing-notes.json` | Yes, as "Cooked for this site by NAME on DATE: yield, active and elapsed time, equipment, observations", only when the record is `accepted`, its `recipeVersion` is current, and `testing-notes.json` says `"status": "cooked"` with the same `cookedBy` and `date`. |

The content version is a short hash of everything that affects what a reader cooks. It is printed in `status.md` and passed to the report form as `v`. Editing the recipe makes an approval or a kitchen record stale, and it drops off the page until it is renewed. `npm run check` warns when that happens. It fails on an approval with no reviewer or date, or on a kitchen record missing a field.

Nothing else on the site may say a recipe was tested (CLAUDE.md, section 4.3). AI drafting, software checks and archive photographs are not evidence of cooking.

## Workflow

1. **Editorial pass.**
   - Read the live page against the editorial checklist below.
   - Correct the recipe in its source file in a commit of its own, then run `npm run build`.
   - Take the new content version from `docs/flagship/status.md`.
   - Set `editorial` to `{status: "approved", reviewer, date, recipeVersion, notes}`.
   - Use `in-review` or `changes-requested` while it is in progress.
2. **Kitchen pass.**
   - Cook the recipe exactly as the page reads at that content version, using the cook's checklist below.
   - Fill in the evidence record and add it to `kitchen[]` with `reviewStatus: "submitted"`.
3. **Review the record.**
   - A second person, or the owner, reads it.
   - If the cook changed something, or the result differed from the page, correct the recipe first. The correction changes the content version, and the dish is cooked again.
   - When the record matches the current page, set `reviewStatus: "accepted"`.
   - Update the recipe's entry in `testing-notes.json`: `status: "cooked"`, `cookedBy`, `date` and `notes`.
4. Run `npm run build && npm run check`, then commit.

## The evidence record

```json
{
  "recipeVersion": "8959455e5814",
  "cook": "Full name as it should appear",
  "date": "2026-11-02",
  "ingredientsUsed": "Brands or specifications that matter: flour protein %, butter salted or not, egg size, banana ripeness",
  "equipment": [{ "item": "loaf tin", "size": "900 g / 23 × 13 cm, metal" }, { "item": "oven", "size": "fan, set to 160°C" }],
  "activeMinutes": 20,
  "elapsedMinutes": 95,
  "yield": "1 loaf, 10 slices",
  "observations": "What it looked, smelled and felt like at each cue in the method",
  "failures": "What went wrong, or \"none\"",
  "adjustments": "Anything done differently from the page, and why",
  "media": ["Paths or links to photographs taken while cooking (the cook's own; never stock)"],
  "reviewStatus": "submitted"
}
```

`reviewStatus` is `submitted`, `accepted` or `rejected`. Times are measured, not copied from the page.

## Editorial checklist

- The title, lede and search description promise only what the page holds: elapsed time with waiting included, servings and diet labels.
- Every ingredient is used in the method, and every quantity in the method matches the list.
- Each stage has a time or an observable cue, and the cue says what to look, smell or listen for.
- The equipment and its size are named where size matters: tins, pans, dishes.
- Substitutions say what changes: flavour, texture, cooking behaviour, or whether it is still the dish.
- Food-handling guidance follows CLAUDE.md section 3. The safety notes cite their source where they depend on one.
- No history, origin or named person is added. Hedge anything unsure, or leave it out.
- The photograph shows the dish and fits the diet label. Its credit line is right.

## Cook's checklist

Before you start:

- [ ] Print or save the page and write its content version (from `status.md`) on it.
- [ ] Note the oven type (fan or conventional), and use an oven thermometer if you have one.
- [ ] Weigh rather than measure by cup where the recipe gives grams.
- [ ] Note the specifications that matter: egg size, flour type, butter salted or unsalted, the brand of any paste or stock.
- [ ] Measure the tins and pans you use (internal size at the top).

While you cook:

- [ ] Start a timer at the first step. Note the clock time at the start and end of each stage and of each wait.
- [ ] Record **active** time (hands on) and **elapsed** time (start to finish, waiting included) separately.
- [ ] At every cue in the method ("golden", "coats the back of a spoon", "a skewer comes out clean"), write what you actually saw and when.
- [ ] If you change anything, write down what and why, even if it seemed minor.
- [ ] Take photographs of the stages and the result. Your own photographs only.

After:

- [ ] Count or weigh the yield.
- [ ] Note anything that failed or nearly failed, and anything in the method that was unclear.
- [ ] Note how leftovers kept, only if you kept them and checked them. Never extend a storage time from one test.
- [ ] Fill in the evidence record above and hand it over for review.
